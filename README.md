## 📐 معماری

```
مرورگر  →  Next.js 16 (پورت 3100)  ──JSON/HTTP──→  Laravel 13 (پورت 8100)  →  SQLite
              رابط کاربری                              فقط API
```

لاراول **هیچ صفحه‌ای رندر نمی‌کند** — فقط JSON برمی‌گرداند (معماری Headless / API-First).
مزیت: همین API بعداً بدون تغییر به اپ موبایل هم سرویس می‌دهد.

| پوشه | نقش |
|------|-----|
| `nextstore-api/` | بک‌اند لاراول (API-only) |
| `nextstore-web/` | فرانت‌اند Next.js |
| `tools/` | PHP و Composer پرتابل (بدون نیاز به نصب) |
| `rodmap.md` | رودمپ کامل ۰ تا ۱۰۰ پروژه (۴۴۰۰ خط) |

## ✨ قابلیت‌های پیاده‌شده

- 🌐 **دوزبانه کامل** با مسیر مجزا (`/fa`, `/en`) و `hreflang` برای سئو
- ↔️ **RTL/LTR خودکار** — `<html dir>` از همان اولین بایت HTML درست است
- 🌗 **دارک/لایت/سیستم** بدون پرش تم (اسکریپت همگام پیش از رندر)
- 📱 **ریسپانسیو** از ۳۲۰px تا ۲۵۶۰px
- 🔍 **جستجوی بین‌زبانی** — تایپ `MacBook` در سایت فارسی، «مک‌بوک پرو» را پیدا می‌کند
- 🗂️ **دسته‌بندی درختی** — انتخاب دسته والد، محصولات همه زیردسته‌ها را نشان می‌دهد
- 🎨 **دیزاین‌سیستم** با توکن‌های OKLCH
- ♿ **دسترسی‌پذیری** — skip-link، `focus-visible`، `aria-label`، `prefers-reduced-motion`
- ⚡ **SSG + ISR** — صفحه اصلی هر دو زبان به‌صورت استاتیک پیش‌رندر می‌شود

## 🚀 راه‌اندازی

### ساده‌ترین راه — یک فایل

```
run.bat
```

این فایل خودش همه‌چیز را انجام می‌دهد:
وابستگی‌ها را بررسی و در صورت نبود نصب می‌کند · فایل `.env` و کلید برنامه می‌سازد ·
دیتابیس و داده نمونه را ایجاد می‌کند · آزاد بودن پورت‌ها را چک می‌کند ·
هر دو سرور را بالا می‌آورد · سلامتشان را تأیید می‌کند · مرورگر را باز می‌کند.

| دستور | کار |
|---|---|
| `run.bat` | بررسی، نصب و اجرای همه‌چیز |
| `run.bat -Fresh` | بازسازی کامل دیتابیس + داده نمونه |
| `run.bat -Prod` | اجرای فرانت در حالت تولید (build + start) |
| `run.bat -Stop` | توقف هر دو سرور |
| `powershell -File scripts\clean-cache.ps1` | پاکسازی کش‌های بازساختنی |

> ⚠️ **درایو C روی این سیستم همیشه نزدیک به پر است.** کش توربوپک در `.next` با هر
> بیلد چند صد مگابایت رشد می‌کند. وقتی فضا تمام شود، Next نمی‌تواند کش را بنویسد و
> صفحه‌ها **بدون خطای آشکار** هیدریشن نمی‌شوند — دکمه‌ها در HTML هستند ولی هیچ
> کلیکی کار نمی‌کند. اگر چنین چیزی دیدی، اول `clean-cache.ps1` را اجرا کن.

اگر پیش‌نیازی نباشد، دقیقاً می‌گوید چه چیزی کم است و راه‌حلش چیست.

### راه دستی

> ⚠️ **نکته این سیستم:** PHP نصب نیست؛ نسخه پرتابل در `tools/php/` است.
> همچنین پورت‌های ۸۰۰۰ و ۳۰۰۰ اشغال‌اند، پس لاراول روی **۸۱۰۰** و Next روی **۳۱۰۰** اجرا می‌شود.

### بک‌اند

```bash
cd nextstore-api

# ساخت دیتابیس و داده نمونه (۳۲ محصول دوزبانه، ۶ دسته، ۱۲ برند)
../tools/php/php.exe artisan migrate:fresh --seed

# اجرای سرور
../tools/php/php.exe artisan serve --host=127.0.0.1 --port=8100
```

### فرانت‌اند

```bash
cd nextstore-web
pnpm install
pnpm dev          # توسعه
# یا
pnpm build && pnpm start   # تولید
```

سپس باز کن: **http://localhost:3100**

## 🧠 تصمیمات فنی

<details>
<summary><b>چرا قیمت‌ها عدد صحیح‌اند و نه اعشاری؟</b></summary><br/>

اعداد اعشاری در کامپیوتر دقیق نیستند: `0.1 + 0.2 === 0.30000000000000004`.
در محاسبات مالی این خطا انباشته می‌شود. قیمت‌ها به **ریال** و به‌صورت
`unsignedBigInteger` ذخیره می‌شوند؛ تبدیل به تومان فقط در لایه نمایش انجام می‌شود.
</details>

<details>
<summary><b>چرا محتوای چندزبانه در ستون JSON است و نه جدول ترجمه؟</b></summary><br/>

`{"fa": "گوشی", "en": "Phone"}` در همان ردیف محصول. مزیت: بدون JOIN اضافه،
کوئری ساده‌تر و سریع‌تر، و افزودن زبان سوم نیازی به مایگریشن ندارد.
</details>

<details>
<summary><b>چرا فیلترها در URL هستند و نه در state؟</b></summary><br/>

لینک قابل اشتراک‌گذاری است، دکمه بازگشت مرورگر درست کار می‌کند، با رفرش از
بین نمی‌رود، و صفحه سمت سرور رندر می‌شود (سئوی بهتر).
</details>

<details>
<summary><b>چرا آرایه کش می‌شود و نه مدل Eloquent؟</b></summary><br/>

`Cache::remember` شیء را serialize می‌کند و هنگام خواندن، unserialize نمی‌تواند
مدل‌ها و رابطه‌های تودرتو را بازسازی کند:
`"The script tried to call a method on an incomplete object"`.
بدتر اینکه بار اول کار می‌کند (کش خالی) و از بار دوم می‌شکند.
راه‌حل: خروجی Resource را به آرایه تبدیل و همان را کش می‌کنیم — سبک‌تر و امن.
</details>

<details>
<summary><b>چرا جستجو از json_extract استفاده می‌کند؟</b></summary><br/>

`json_encode` در PHP کاراکترهای غیرانگلیسی را escape می‌کند، پس در دیتابیس
`{"fa":"گلکسی"}` ذخیره می‌شود.
در نتیجه `WHERE name LIKE '%گلکسی%'` هرگز تطابق پیدا نمی‌کند.
با `json_extract(name, '$.fa') LIKE ?` روی مقدار رمزگشایی‌شده جستجو می‌کنیم.
</details>

---

<details>
<summary><b>چرا ثبت سفارش قیمت را از سبد کاربر نمی‌خواند؟</b></summary><br/>

قیمت هر قلم هنگام ثبت سفارش دوباره **از دیتابیس** خوانده می‌شود، نه از
داده‌ای که کلاینت فرستاده. بدون این، کاربر می‌توانست با دستکاری درخواست،
محصول ۹۰ میلیونی را ۱۰۰۰ تومان بخرد.

همچنین کل عملیات داخل یک تراکنش با `lockForUpdate` روی ردیف محصول انجام
می‌شود، تا دو کاربر هم‌زمان نتوانند آخرین کالای موجود را بخرند.
</details>

<details>
<summary><b>چرا سفارش «عکس لحظه‌ای» ذخیره می‌کند؟</b></summary><br/>

نام محصول، قیمت و آدرس گیرنده در خود سفارش کپی می‌شوند، نه ارجاع به
جدول اصلی. اگر ادمین فردا قیمت را عوض کند یا کاربر آدرسش را ویرایش کند،
فاکتور قدیمی نباید تغییر کند — فاکتور یک سند مالی است.
</details>

<details>
<summary><b>چرا درگاه پرداخت پشت یک اینترفیس است؟</b></summary><br/>

`PaymentGatewayInterface` قرارداد را تعریف می‌کند و `MockGateway` آن را
برای دمو پیاده می‌کند. افزودن زرین‌پال یا Stripe فقط یک کلاس جدید و یک
ردیف در نگاشت درگاه‌ها می‌خواهد — هیچ کد موجودی تغییر نمی‌کند.

تأیید نهایی همیشه سمت سرور انجام می‌شود؛ بازگشت کاربر از درگاه به‌تنهایی
هرگز سفارش را «پرداخت‌شده» نمی‌کند.
</details>

## 🧪 تست

### بک‌اند

```bash
cd nextstore-api
../tools/php/php.exe artisan test                      # ۲۲۵ تست Pest
../tools/php/php.exe vendor/bin/pint                   # قالب‌بندی کد
../tools/php/php.exe ../tools/composer.phar analyse    # تحلیل ایستا (PHPStan)
../tools/php/php.exe artisan docs:api                  # ساخت مستندات API
```

مستندات هر ۱۲۴ اندپوینت در [`nextstore-api/docs/API.md`](nextstore-api/docs/API.md)
است.

⚠️ آن فایل **دستی نوشته نمی‌شود**: از روی جدول مسیرهای لاراول و
docblock خودِ کنترلرها ساخته می‌شود. پس اگر توضیحی غلط بود، جای
اصلاحش همان متد کنترلر است نه فایل مستندات — وگرنه دفعه‌ی بعد که
فرمان اجرا شود، اصلاح شما پاک می‌شود.

⚠️ تحلیل ایستا را با اسکریپت composer اجرا کنید نه مستقیم: سقف حافظه‌ی
پیش‌فرض PHP برای این پروژه کم است و خطایش («Child process error») شبیه
باگ خود ابزار به نظر می‌رسد نه کمبود حافظه.

### فرانت‌اند

```bash
cd nextstore-web
pnpm typecheck                 # tsc
pnpm lint                      # eslint
pnpm check:i18n                # برابری کلیدهای fa و en
pnpm test:e2e                  # هر ۲۲ سوئیت سرتاسری، پشت سر هم
pnpm test:e2e checkout         # فقط آن‌هایی که «checkout» در نامشان است
pnpm shots                     # عکس‌برداری برای بازبینی چشمی
```

### یکپارچه‌سازی پیوسته

`.github/workflows/ci.yml` روی هر push و PR به `main` و `develop` اجرا
می‌شود: سه job موازی (لاراول · نکست · برابری ترجمه‌ها).

⚠️ هوک پیش از کامیت فقط فایل‌های **استیج‌شده** را بررسی می‌کند و عمداً
تست اجرا نمی‌کند. CI کل پروژه را با تست کامل می‌سنجد — و برخلاف هوک،
نمی‌شود دورش زد.

⚠️ تست‌های سرتاسری به **سرور در حال اجرا** نیاز دارند (`run.bat`). سریال
اجرا می‌شوند چون روی یک دیتابیس مشترک کار می‌کنند.

تست‌های Pest روی SQLite **در حافظه** اجرا می‌شوند (`phpunit.xml`)، پس
داده‌ی دمو هرگز دست نمی‌خورد. کل سوئیت حدود ۳۵ ثانیه طول می‌کشد.

| پوشه | چه چیزی را می‌آزماید |
|---|---|
| `tests/Unit` | محاسبه‌ی تخفیف — سقف، گِردکردن صحیح، مبلغ منفی |
| `tests/Feature/Order` | ثبت سفارش: دستکاری قیمت، برگشت تراکنش، کسر موجودی، کوپن |
| `tests/Feature/Cart` | عملیات سبد، ادغام سبد مهمان، هر شاخه‌ی رد کد تخفیف |
| `tests/Feature/Catalog` | فیلتر، جستجوی بین‌زبانی، پنهان‌ماندن پیش‌نویس‌ها، بنرها |
| `tests/Feature/Review` | صف تعدیل، بازمحاسبه‌ی امتیاز، رأی مفید |
| `tests/Feature/Support` | چرخه‌ی تیکت، فرم تماس، اعلان‌ها، ایمیل‌های صف‌شده |
| `tests/Feature/Auth` | ثبت‌نام، هش رمز، حساب مسدود، ابطال توکن، بازیابی رمز |
| `tests/Feature/Admin` | کنترل دسترسی، IDOR، نشت هش رمز و ایمیل، فهرست سفید تنظیمات |
| `tests/Feature/Shop` | فهرست سفید تنظیمات، یکی‌بودن نرخ ارسال با سبد |

تست‌های سرتاسری مرورگری جدا هستند و در `nextstore-web/scripts/e2e-*.mjs`
قرار دارند (۲۲ سوئیت).
